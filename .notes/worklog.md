- 2026-10-13, planning: inspected the scaffold and profiled the fixed seed: 500 people, 12 projects, 126,195 assignments spanning 2025-06-02 through 2027-01-03. Repeated-looking assignments have distinct IDs; all must contribute to totals.
- Proposed calculation rules (not implemented): Monday weeks, inclusive assignment dates, Mon–Fri workdays, and selected-range clipping with matching capacity proration. The schema has no capacity history, so a weekly-hours edit applies to past weeks too; make that scope visible.
- Independent seed checks under those rules: Ana has 40h/40h in the week starting 2025-12-29; Bo 32h/40h, Cem 4h/20h, Dee 45h/40h, and Eli 20h/0h in the week starting 2026-01-05. The week starting 2026-10-12 has no allocations; retain the scaffold's initial range for the demo.
- Proposed implementation: aggregate only overlapping assignments in SQL; use optional server roster pagination and bounded table rendering. Confirm saves before refreshing the active range, reject obsolete reads across navigation and saves, and distinguish a failed save from a successful save whose refresh failed.
- Verification priorities: hand-checked seed totals, partial/weekend/year boundaries, zero capacity, failed-save draft retention, late-response races, and short/two-year ranges in the browser. Docker is available, but services were not started during this planning-only pass; application code is unchanged.

- 2026-10-13, deeper research: user has no guidance beyond the repo and expects a complete assignment submission. Ambiguities need explicit, defensible defaults and verification, not unfinished requirements waiting on an external owner.
- Correction to the earlier plan: weekday counting and partial-week proration are not specified. The recorded totals verify arithmetic only under the proposed weekday convention. Prefer whole-week selection with visible Monday–Sunday boundaries; prorating would additionally assume everyone's weekly hours are evenly distributed over five days.
- History strengthens inclusive endpoints (Cem has a same-day assignment) and additive rows: each of 8,413 person/project/date groups contains 14 equal rates plus one double rate, reconstructing the old seed's daily hours. Deduplicating equal tuples would retain only 3/16 of the hours; keep decimal precision until aggregation.
- Save handling needs three outcomes: rejected, confirmed saved but refresh unavailable, and unconfirmed after transport failure. Aborting a browser request is not rollback; an immediate read may race a still-running write. Preserve drafts, serialize saves per person, reconcile unconfirmed outcomes, and never offer a write retry for a failed refresh.
- A GET begun during a PATCH can return stale capacity after success even if its date range is current. Invalidate all prior read generations at save completion, guard success/error/finally, refetch the current query, and keep draft state keyed by person ID outside paginated rows. Cross-session lost updates are a separate concurrency limitation to document or address with a defined conditional update.
- PATCH /people does not guarantee HTTP-cache invalidation of derived /capacity URLs; capacity reads need explicit freshness. Compute one response from one SQL snapshot, use UPDATE ... RETURNING, and avoid re-querying hours per week across a concurrent save. References: https://react.dev/reference/react/useEffect ; https://www.rfc-editor.org/rfc/rfc5789.html ; https://www.rfc-editor.org/rfc/rfc9111.html#section-4.4 ; https://www.postgresql.org/docs/17/transaction-iso.html .
- Pagination and a two-year maximum are engineering choices, not explicit API requirements. Preserve every-person behavior by default; label page scope, make the whole roster findable, and never imply an empty page proves nobody on the team is over capacity. Browser rendering and payload size still need measurement after implementation.
- Standard Compose DB startup failed because Docker could not mount this checkout's Downloads path. An isolated temporary PostgreSQL 17.11 container loaded the unchanged schema/seed via stdin for read-only experiments; this does not verify the normal application startup. Resolve folder access or run an unchanged checkout from an accessible path before final browser acceptance.
- Temporary query checks passed an independent Decimal/day-enumeration oracle for eight ranges (61,750 person-week comparisons), including initial, partial, weekend-only, year-boundary, empty, one-day, two-year/all-people and two-year/50-people cases. These establish arithmetic under inclusive Mon–Fri clipping, not the business meaning of a date range.

These exclude HTTP/browser work; bound-query plans and production-scale rendering remain implementation checks.
